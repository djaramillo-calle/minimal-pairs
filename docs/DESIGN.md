# Design brief — Minimal Pairs (Android)

A minimal-pair **perception** trainer for British English following
high-variability phonetic training (HVPT): the learner hears one word of a pair
in a random one of several voices, taps which word he heard, gets instant
feedback, repeats. One tool inside an English-coaching system: the coach tunes
it from outside through `plan.json`, the app publishes results as files the
coach pulls (`docs/CONTRACT.md`). Owner: an adult learner, L1 Spanish, UK-based,
Poco F7 Pro on Android 15, sideloads APKs.

## Decisions (fixed)

- Kotlin, Jetpack Compose (Material 3), `minSdk 26`, `targetSdk 35`,
  `compileSdk 35`, single module `:app`, applicationId
  `com.djaramillo.minimalpairs`. AGP 8.7.3, Kotlin 2.0.21 with the Compose
  compiler plugin, Compose BOM 2024.12.01, kotlinx-serialization 1.7.3
  (`ignoreUnknownKeys = true`, `isLenient = true`, `explicitNulls = false`),
  androidx.documentfile 1.0.1, activity-compose 1.9.3, lifecycle 2.8.7. JUnit 4
  for unit tests. Gradle wrapper 8.14.3 committed (`gradle-wrapper.jar` included).
- No backend, no accounts, no analytics, no permissions beyond `INTERNET`
  (optional clip-pack download from this repo's GitHub Releases on first run).
  Offline after that. No third-party runtime libraries beyond AndroidX/Kotlin.
- Data folder: `Documents/MinimalPairs/` chosen via the Storage Access
  Framework (`ACTION_OPEN_DOCUMENT_TREE`, `takePersistableUriPermission` read +
  write, `EXTRA_INITIAL_URI` pointing at Documents), URI remembered in
  SharedPreferences. File layout and schemas: `docs/CONTRACT.md`. The app also
  keeps private copies of `state.json` and every session file under
  `filesDir/mirror/` and re-publishes any session file missing from the folder
  at every launch, so a session is never lost if the folder was unavailable.
  `state.json` is written as `state.json.tmp` → delete old → rename, so the
  folder never holds a half-written state. Session files are written once.
- Catalog: `data/catalog/catalog.json` + `data/catalog/catalog-version.txt`,
  generated by `scripts/build-catalog.py` from the vendored sources in
  `data/sources/` (Britfone 3.0.1, MIT; hermitdave FrequencyWords `en_50k`,
  MIT). The Gradle build adds `data/catalog` as an assets source dir, so the
  app reads `assets/catalog.json`.
- Clips: `scripts/render-clips.py` renders every trainable word with Azure
  neural TTS (`AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` from the environment,
  never printed, never written). Output format
  `webm-24khz-16bit-24kbps-mono-opus` (Opus in WebM/Matroska, which Android's
  `MediaExtractor` decodes on every API ≥ 21; Ogg/Opus is *not* safe below
  Android 10). Six en-GB voices, 3 female + 3 male: `en-GB-SoniaNeural`,
  `en-GB-LibbyNeural`, `en-GB-HollieNeural`, `en-GB-RyanNeural`,
  `en-GB-ThomasNeural`, `en-GB-AlfieNeural`. One clip per word per voice, path
  `clips/<voice>/<word>.webm`, plus `clips/index.json`. Never committed.
  If the full pack is ≤ 40 MB it is bundled whole in the APK assets
  (`app/src/main/assets/clips/`, gitignored, copied by `render-clips.py
  --install-assets` and by CI); otherwise the two highest-default-weight
  contrasts are bundled and the whole pack ships as `clips.zip` on the GitHub
  Release, which the app offers to download on first run into
  `filesDir/clips/`. A committed placeholder pack (`data/placeholder-clips/`,
  ~12 words × 2 voices) is used whenever no rendered pack exists so the build
  never fails; its `index.json` says `"complete": false`.
- Audio latency budget: **sound within 150 ms of the tap**. Clips are decoded
  to 16-bit PCM in memory (`MediaExtractor` + `MediaCodec`) one trial ahead:
  the scheduler draws lazily (the next draw depends on the answer, see
  `docs/ADAPTATION.md`), so trial 1's target and foil are decoded during the
  Home → Trial transition behind a short spinner, and trial `i+1` is drawn and
  decoded the moment trial `i` is answered, during the feedback pause. Leading
  silence below −50 dBFS (RMS over 5 ms, so a stray click does not count) is
  trimmed, and playback uses a pre-created `AudioTrack` (static mode per clip,
  written once at decode time), so every tap — auto-play, replay, hear-word —
  is a `play()` on a filled track. Reaction time starts at the moment the track
  starts playing. Decoding a <1 s clip at 24 kHz mono takes ~10–30 ms; the
  session holds at most 8 tracks. Playback takes transient audio focus with
  ducking so music in another app is lowered, not talked over. A clip that
  cannot be decoded never strands the session: the trial offers Retry / Skip
  (a replacement draw with the same index; nothing is recorded for it).
- Session logic: `plan.trials_per_session` trials (default 40, ≈3 minutes),
  contrasts weighted per `docs/ADAPTATION.md`, random voice per trial, half the
  trials on untrained words. Domain logic (scheduler, state update, record
  building, plan merge) is pure Kotlin with an injected `kotlin.random.Random`
  and unit tests; no Android types in it.
- Screens: **Home** (today's drill button, streak, last untrained score per
  contrast, coach note, folder/pack warnings), **Trial** (big play/replay
  button, two large word buttons, progress `12/40`, instant feedback with the
  differing sounds highlighted in IPA, tap-to-hear both words when feedback is
  `full`), **Summary** (overall, per contrast, mean RT, file written),
  **Settings** (folder picker + status, the coach plan read-only, manual
  override, clip pack status + download, versions). Large touch targets, works
  one-handed, dark theme follows the system.
- Coach scripts: `scripts/plan-from-ledger.py`, `scripts/sessions-summary.py`,
  Python 3 stdlib only, each with `--selftest`. `scripts/check.sh` runs the
  Python selftests, the catalog build check and the Android unit tests.
- CI: `.github/workflows/release.yml` on every push to `main` and on tags:
  build the release APK on `ubuntu-latest`, sign with the keystore from secrets
  `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
  `ANDROID_KEY_PASSWORD` when present (debug key otherwise, and the release
  notes say so), render or restore the clip pack (cache keyed by catalog
  version + voices, else the previous release's `clips-<catalog>.zip` when it
  is a complete pack for the same catalog, else Azure when the secrets are
  present; placeholder otherwise, and then the release is not marked latest so
  `releases/latest/download/clips.zip` keeps serving the last real pack),
  publish a GitHub Release with the APK and `clips.zip`. The app refuses a
  downloaded pack whose `index.json` says `complete: false`, or that was
  rendered for another catalog and does not cover this catalog's words.

## Catalog (`data/catalog/catalog.json`)

```json
{
  "version": "2026-09-11.2",
  "generated": "2026-09-11T10:00:00Z",
  "sources": {"pronunciation": "Britfone 3.0.1 (MIT)", "frequency": "hermitdave/FrequencyWords en_50k 2018 (MIT)"},
  "voices": ["en-GB-SoniaNeural", "..."],
  "contrasts": [
    {
      "id": "i/ii", "label": "ship / sheep", "kind": "vowel",
      "phonemes": ["ɪ", "iː"], "default_weight": 0.6,
      "trainable": true, "production_only": false,
      "description": "Short ɪ versus long iː. Spanish has one /i/.",
      "pairs": [
        {
          "id": "i/ii:ship-sheep",
          "a": {"word": "ship",  "ipa": "ʃɪp",  "rank": 1834, "band": "high"},
          "b": {"word": "sheep", "ipa": "ʃiːp", "rank": 3120, "band": "mid"},
          "diff": ["ɪ", "iː"], "variant": "ɪ/iː", "position": "medial", "trainable": true
        }
      ]
    }
  ]
}
```

- `ipa` is the Britfone transcription with spaces removed and stress marks kept
  (`ˈ`, `ˌ`, in Britfone's position directly before the vowel, `pɹˈaɪs`);
  Britfone's `ɐ` is written `ʌ` in the catalog (STRUT), `ɹ` stays `ɹ`. The
  Trial screen renders the mark at the syllable onset as standard IPA does
  (`/ˈpɹaɪs/`, `Ipa.display`). `diff` lists the phoneme of `a` and of `b` at
  the differing slot (`""` for an absent phoneme, e.g. `["", "h"]` for
  our/hour-type pairs or `["", "t"]` for walk/walked).
- A pair is **minimal** when the two phoneme sequences (stress marks stripped,
  Britfone tokens compared as tokens, so `tʃ` is one unit) differ in exactly
  one slot by substitution, or (for `-ed` and `h` only) by one insertion. Pair
  order: `a` is the first phoneme of the contrast's `phonemes` list.
- `band` by frequency rank in `en_50k`: `high` ≤ 2000, `mid` ≤ 8000, `low`
  ≤ 50000, `rare` = not in the list. A pair is `trainable` only if both words
  are in the list (not `rare`), spelled with `a–z` only, have exactly one
  Britfone pronunciation (variants `(1)`, `(2)` are skipped as homographs),
  and are not in the exclusion list of the script (offensive words,
  abbreviations, slang, interjections, letter names, and a hand-kept list of
  proper nouns, since neither source carries case).
- `position`: `initial` when the differing slot is the first phoneme, `final`
  when it is the last, else `medial`.
- Contrasts (id — phonemes — notes):
  `i/ii` ɪ/iː · `cat/cut` æ/ʌ (Britfone `ɐ`) · `long-back` variants ɒ/ɔː and
  æ/ɑː · `schwa` ə vs a full vowel in an unstressed syllable (few true pairs;
  ship whatever exists, `trainable: false` on the contrast if fewer than 6) ·
  `th` variants θ/t, θ/s, ð/d · `b/v` · `s/z` · `j/y` dʒ/j · `-ed` final t or d
  present vs absent (`walk/walked`, `play/played`; not the extra-syllable
  `wanted`; only real inflections, so `see/seed` and nonstandard `waked`
  are not -ed pairs; derivational forms like `skill/skilled` stay, the
  contrast is perception of a final t/d) · `h` h vs zero, initial only · `sh/ch` ʃ/tʃ · `er/or` ɜː/ɔː ·
  `s-cluster` production-only, `trainable: false`, `pairs: []`.
  Target 30–80 trainable pairs per contrast where the lexicon allows; report
  the real counts, and beside them the number of distinct sound pairs
  (homophone spellings such as sir/saw, sir/sore count once). Default weights (relative, from the learner's ledger):
  th 1.0, s/z 0.8, i/ii 0.6, b/v 0.5, cat/cut 0.4, long-back 0.3, j/y 0.3,
  -ed 0.3, h 0.2, sh/ch 0.2, er/or 0.2, schwa 0.15, s-cluster 0.
- `pairs` sorted by the sum of ranks (commonest first). A word may appear in
  several pairs and contrasts; the clip is rendered once.

## Clip pack `index.json`

```json
{"version": 1, "catalog_version": "2026-09-11.2", "format": "webm/opus 24 kHz 24 kbps mono",
 "voices": ["en-GB-SoniaNeural", "..."], "words": ["ship", "sheep", "..."],
 "complete": true, "contrasts": ["i/ii", "..."], "files": 7800, "bytes": 37000000}
```

`complete: false` means the pack holds only some contrasts (placeholder or
partial bundle); the app then offers the download and, until it is there,
schedules only contrasts whose words are all present.
